### Bug A：详情页 404 —— 静态导出与动态路由不兼容
`output: export` 时 `[id]` 动态段只导出 `generateStaticParams()` 预生成的 id

  否则 build 直接报错）

## 第三轮：时间线中文化 / AI 报告修复 / UI 优化

### AI 报告永远「生成中…」的真因
`app/routers/matches.py:341` 调 `_score(events)`，而函数签名是 `_score(m, events)`
→ 每次请求抛 `TypeError` → 500 → 前端 `usePolling` 只拿到 error、data 一直是 null，
于是永远显示「报告生成中…」。加 `_score(m, events)` 即可。

**教训**：`usePolling` 的 error 之前没被用上，所以后端 500 在界面上表现为「加载中」。
详情页凡是用 usePolling 的地方都应该消费 `error`，否则故障不可见。

### 事件时间线中文化
ESPN `keyEvents[].text` 是英文长句。新增 `zh_event_detail(text, kind)`（espn.py）：
按句式解析（进球/乌龙/红黄牌/换人/点球未进/低级别赛事简写 "Player (Team) Goal at 16'"），
拼成中文短句，并把队名/人名换成中文。
`parse_event_text()` 顺带补 `player/related` —— ESPN 对黄牌、换人经常不给
`athletesInvolved`，旧代码 player_id 全是 NULL，时间线上点不了球员。
已回填 297 条事件的球员关联。

API 加 `EventOut.detail_cn`（读时翻译，不动库里存的原文，历史数据自动生效）。

### 队名中文化补齐
